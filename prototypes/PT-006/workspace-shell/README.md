## 18 видов и новый материал

| Вид | Материал |
|---|---|
| Scenario / Context | Общий старт, внешние якоря, динамичность проекта, команда и инженерная среда |
| Actual Events | Фактические события A/B; полная лента для навигации |
| Current State | Известные требования, фактический CURRENT и файлы выбранного момента |
| Requirement Model | Ненормализованные фактические требования; прогнозы не становятся фактом автоматически |
| Architecture | ACTUAL и PLANNED выбираются в явном контексте; один ID может иметь разные версии |
| Architecture Planning | Полная цель выбранного Step из выбранной PlanRevision |
| Plan | Один Plan: Steps, другая плановая работа, зависимости, возможные события, ожидания и сроки |
| Forecasts / Deadlines | Конкретные прогнозные требования, основания ожиданий маршрутов, оценка завершения отдельно от обещания |
| Planned Change Axes | Направление, значимость, горизонт, основание и исторический пересмотр |
| Actual Hot Paths | Наблюдавшиеся изменения, отдельно от прогнозных осей |
| Evolution Impact | Влияние Step одного маршрута, отдельно от полного снимка |
| Impact History / Future | Фактические architecture/file переходы и отдельные условные будущие impacts |
| Evolution Fitness | Цель и контекст каждого подготовленного маршрута, миграция, соответствие Plan, отдельные затраты |
| Implementation / Files | Фактическое дерево файлов и отдельные плановые эффекты |
| Requirement / Implementation Trace | Собственные связи requirement–architecture–file, включая историю note |
| Event / Entity Explorer | Событие, новые требования и связанные architecture/file изменения |
| Cross-Architecture Comparison | Общий стимул и объяснённые последствия A/B; отдельные фактические cursors |
| Work Dynamics / Hot Paths | Работа по цели, knowledge/contracts/dependencies, compatibility/rollout, ожидание, откат, эксперимент, feedback, autonomy, cost/time provenance и фактический исход срока |

Каталог имеет Preview / State / JSON Schema / History. Каждый вид имеет собственный State.
Проекции раскрывают канонические source State/Schema. Scenario и Trace имеют собственные факты; Trace History включает links.
При выборе архивной PlanRevision доступны её сохранённые данные в отдельном плановом контексте. CURRENT разрешается из фактического контекста.
Выбор Step/маршрута/вкладки не является выполнением работы или фактическим событием.
Исторический State доступен только для чтения. Прямые JSON-правки последнего State не создают событий.

## Навигация и Workspace

Architecture A/B — отдельные ветки с отдельными Screens и геометрией окон.
На новом Workspace четыре примерных экрана: Обзор, Разбор изменений, Факты и связи, План и прогнозы.
Окна, вкладки и данные независимы: закрытие окна сохраняет State. Typed singletons ограничены экраном.
Сохранённая пользовательская раскладка не заполняется новыми окнами автоматически. Используйте + Окно и поиск каталога.
Drag, обмен геометрией, прокрутка колёсиком/краем и fit-on-drop с gap сохранены.
Reset сбрасывает и контент, и раскладку после явного подтверждения.

## Итерация механики Workspace · 2026-10-10

[Рабочий контракт и журнал](../PT006_WORKSPACE_INTERACTIONS_2026-10-10.md) фиксирует реализацию WSC-PR-01–04. Общая механика Shell и профиль Architecture Simulator разделены; 79/79 тестов, build и lint проходят, ограниченный браузерный smoke-test успешен. Пользовательская приёмка ещё не выполнена.

Реализовано универсальное событие `open-content` с адресом `{ profileId, instanceId }`: поиск адресованного экземпляра содержимого среди окон и экранов, переключение, показ окна и подсветка; если зарегистрированной вкладки нет, она создаётся в новом окне. Shell не зависит от `ContentKind` симулятора. Идентичность позволяет различать два Markdown-файла одного типа (проверено на условных дескрипторах без реализации Markdown Viewer).

Обычное колесо над шапкой окна прокручивает вкладки горизонтально, когда они переполнены, и **не прокручивает рабочее поле** даже на краях полосы или без переполнения. Вся нижняя панель главного заголовка Shell принимает обычное колесо для вертикальной прокрутки Workspace; снизу есть подсказка «↕ Прокрутка рабочего поля». Добавлен запас пространства для прокрутки даже при обычной раскладке. Ctrl+колесо не перехватывается. Доступны кнопки и индикация скрытых вкладок. Кнопка «Просмотр» в шапке Shell скрывает служебные элементы окон, сохраняя клики в содержимом и переходы по событиям; режим сохраняется в браузере. WSC-PR-04 переносит 18 видов, A/B, модель, State/Schema/History, инспекторы, хранилище и стили симулятора в отдельный профиль. Layout-v3 и content-v6 сохраняются без принудительного сброса.

## Исторический пример

- A-01: API отсутствует, есть src/booking.ts. A-02: появляется API и src/api/booking.ts; старый файл удалён.
- EXT-01: R-A3 ещё не известно. A-04: подписанный договор раскрывает R-A3.
- Plan R1: FORECAST онбординга, неопределённый IF CONTRACT и интеграционная ось.
- Plan R2: ожидания и оси меняются по информации A-04/B-04. Это не переписывает R1.
- B R1: обещание 30 апр, оценка 27 апр. B R2: обещание пересогласовано на 15 мая, оценка 18 мая.
- B-05, 16 мая: отдельный фактический исход пропуска обещания. На B-04 этого факта нет.
- Выбор старого Plan сохраняет CURRENT. ACTUAL CURRENT и одноимённый PLANNED target разрешаются отдельно.
- Правка порядка live-ленты не меняет архивные знания A-02. Полная лента остаётся для навигации.
- Неизвестное или изменённое архивное событие не получает чужой State; кнопка «К последнему State» доступна.
- История показывает порядок Steps, собственные Trace links и фактические sources проекций.

- shell/workspace.ts / shell/windowDrag.ts: универсальная геометрия, вкладки, перенос и события окон.
- tests/shell.test.mjs и tests/ui-smoke.cjs: новая механика и браузерная проверка.
