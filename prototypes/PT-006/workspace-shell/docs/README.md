## Как разделены обязанности

- **Shell**: универсальные действия с экранами, окнами, вкладками, их размещением и переходами. Не знает предметных фактов симуляции.
- **Workspace**: **в текущем TypeScript** — сохранённая модель раскладки. **В кандидатной архитектуре** — полноценная рабочая среда с контекстами, ресурсами и инструментами. Эти значения нельзя выдавать за один уже реализованный API.
- **Profile**: регистрирует содержимое и его представления, предоставляет предметные данные, State/Schema/History и операции. Сейчас подключён только Architecture Simulator.
- **Scope Mechanisms**: предлагаемые переиспользуемые механизмы взаимодействий. Пока нет общего runtime и соответствующих папок исходников.

## Карта каталогов

```text
src/
├── App.tsx                        # монтирует один профиль в один Shell
├── shell/                        # универсальный UI и layout-модель
└── profiles/
    └── architecture-simulator/   # предметный State, History, рендеринг, A/B
docs/
├── shell/                        # факты о Shell
├── workspace/                    # текущая модель + кандидатная модель и будущий кодовый план
├── profiles/                     # роль профиля и профильные входные страницы
└── architecture-simulator/       # подробные документы симулятора (сохранены пути)
tests/                             # unit и UI-smoke проверки
```

Документация **частично** повторяет структуру кода, но не моделирует несуществующие каталоги. В частности, сейчас нет самостоятельных `src/workspace/`, `src/integrations/` и `src/**/scope-mechanisms/`.

## Статусы и история

**CURRENT / Git main** — реализация на опубликованной ветке `main`; **LOCAL UNPUBLISHED** — экранные изменения, существующие только в незакоммиченном рабочем дереве на 2026-10-11; **CANDIDATE** — предлагаемая модель или следующий план, не готовый runtime; **HISTORICAL** — датированная проверка определённой итерации. Эти статусы не взаимозаменяемы.

Датированные решения/проверки: [Workspace WSC-PR-01–04](../../PT006_WORKSPACE_INTERACTIONS_2026-10-10.md), [исправления PT-006](../../PT006_REMEDIATION_2026-10-10.md). ## Правило сопровождения

Одну смысловую истину описывает один владелец: механика Shell — в `docs/shell`, текущее состояние Workspace — в `docs/workspace`, предметные правила симуляции — в `docs/architecture-simulator`. Остальные README кратко объясняют назначение папки и ссылаются на этот источник. При смене реализации обновляют соответствующий раздел и явно датируют проверку, а не переписывают старые журналы.
