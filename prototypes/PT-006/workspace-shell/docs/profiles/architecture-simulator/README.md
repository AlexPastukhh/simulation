# Architecture Simulator — предметный профиль PT-006

**CURRENT / G-CODE-02.** Один профиль с подготовленной симуляцией **одного приложения и двух альтернативных архитектур A/B**. Это не общий движок причинных сценариев, не автоматическое исполнение Steps и пока не универсальный Scope Engine.

## Предметные документы

- [Система контента и достоверность](../../architecture-simulator/CONTENT_SYSTEM.md) — различия Actual, Planned и Forecast; PlanRevision/BASE, история, общие события A/B, связи D/S/N/L/C.
- [18 видов](../../architecture-simulator/CONTENT_VIEWS.md) — назначение каждого представления, State/Schema/History, ссылки и размещение в **новых** четырёх экранах.
- [Код профиля](../../../src/profiles/architecture-simulator/README.md) — реализация State, History, рендеринга, контекстных копий и миграций.

**Actual Events** определяют известный фактический срез. Выбор Plan Step не делает прогноз фактом и не исполняет изменение. Исторические снимки и PlanRevision подготовлены автором; прямое изменение live State не переписывает архив. Профильные JSON Schema описывают форму данных, не существование всех предметных объектов.

## Пользовательские режимы

**Отдельные раскладки A/B (прежнее поведение):** кнопки Architecture A и Architecture B переключают целиком сохранённую раскладку и соответствующий `DemoStore`. Данные `pt006-simulator-content-[A|B]-v6` и экраны `pt006-simulator-layout-[A|B]-v3` остаются доступными.

**«⊞ Общий Workspace» (новое поведение):** A и B подключаются как два источника **на одних экранах**. Можно открыть обычную Architecture A и обычную Architecture B в разных окнах одного Screen, не переключая всё рабочее поле. Событие `open-content` в одном Context сохраняет его `contextId`, не подменяет B на A.

**«+ Контекст» → «Эволюция архитектуры»:** создаёт **одну независимую копию State A** и комплект четырёх начальных экранов: «История и факты», «Архитектура и реализация», «Планирование», «Результаты и сравнение». Все 18 видов доступны в новом контексте; копирование не меняет A/B данные и не создаёт новые фактические события.

**«+ Контекст» → «Минимальный контекст»:** создаёт экран с редактируемыми требованиями и заметками без подготовленной History. Сохранение выполняется независимо от симуляции. В минимальном контексте не предлагаются 18 симуляционных видов как будто они уже обеспечены предметными данными.

«+ Экран» предлагает только **пустой экран** и **копию текущего**. Профильные экранные рецепты используются для создания Context, не появляются четырьмя отдельными предметными пунктами в общем меню.

## Хранение и ограничения

Копии и минимальные Context сохраняются в `pt006-simulator-context-copies-v1`. Общая раскладка — в `pt006-simulator-multicontext-layout-v1`. Существующие legacy данные и старые раскладки A/B **не заменяются**; первый общий Workspace импортирует их размещение как отдельную копию. Контекстная копия содержит `templateId`, `sourceId` и собственный State.

Профильное представление **Comparison пока читает `allData.A/B` напрямую**, даже если пользователь находится в новой рабочей копии. Это **частная A/B операция**, а не настроенный Scope Mechanism, не готовая произвольная композиция между выбранными Context. Такое сравнение запланировано для [G-CODE-03](../../workspace/NEXT_CODE_PLAN_CANDIDATE.md).

**Общие vs view-local selections** пока не разделены как самостоятельные универсальные механизмы: для подготовленной симуляции часть выбранного события и Plan Step остаётся в State каждого Context. Реального второго профиля нет. Не считать новый общий Workspace завершённой межпрофильной платформой.
