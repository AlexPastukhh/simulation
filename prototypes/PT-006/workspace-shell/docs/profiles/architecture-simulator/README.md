# Architecture Simulator — предметный профиль PT-006

**CURRENT: одна подключённая профильная реализация.** Это подготовленная авторская симуляция **одного приложения и двух альтернативных архитектур A/B**; не общий движок для произвольных причинных моделей или автоматического исполнения Steps.

- **[Каталог 18 видов](../../architecture-simulator/CONTENT_VIEWS.md)** — вопросы каждого вида, реальные State/Schema/History и связи с другими видами.

- **[Общий Shell](../../shell/README.md)** — создание и открытие окон, вкладок, экранов и навигация; профильные события `open-content` не выполняют Steps.

## Предметные источники, а не обязательные структуры Shell

**Actual Events** определяют сохранённый фактический срез. **CURRENT** — известные на выбранный момент требования, фактическая архитектура, реализация и работа. **Plan/PlanRevision** содержит Step, другую работу, условия, прогнозы, обещания и сроки; у архивной ревизии есть неизменяемый фактический BASE. Плановый целевой ArchitectureSnapshot и Evolution Impact **не становятся фактическими** при выборе Step. **Forecast/Deadline/Actual Outcome** различаются; также различаются Planned Change Axes и Actual Hot Paths.

Контент симулятора предоставляет отдельные схемы и видимые состояния для 18 видов; некоторые виды — производные представления над общими данными, а не самостоятельные копии архитектуры или истории. Не путать предметный вид **Scenario / Context** с будущим универсальным `Workspace Context` и `architecture.selectedContext:'actual'|'planned'` с Context Instance.

В A/B использованы общий начальный случай и общий внешний стимул, но причинно зависимые последствия у каждой ветки могут отличаться. Это **scripted fixture**, не универсальный вычислитель вероятностей или политики победителя. Сопоставление A/B в нынешнем `comparison` — специальный профильный вид с доступом к `allData.A/B`, не общий инструмент Scope Mechanism.

## Экраны и версии

**CURRENT / опубликованный `main`:** четыре экрана «Обзор», «Разбор изменений», «Факты и связи», «План и прогнозы» с размещением части видов во вкладках общих окон. Кнопка «+ Экран» создаёт пустой экран. Существующие пользовательские раскладки при запуске не заменяются автоматически.

**LOCAL UNPUBLISHED / следующий этап:** в рабочем дереве подготовлены отдельные четыре экрана «История и факты», «Архитектура и реализация», «Планирование», «Результаты и сравнение», меню добавления экранных шаблонов и их набора. Они охватывают 18 видов, но не скопированы в опубликованный `main`. [Предварительный план следующего кода](../../workspace/NEXT_CODE_PLAN_CANDIDATE.md) сохраняет это состояние и открытые решения. Идея предоставить **один Context Template** с четырьмя экранами относится к [кандидатной модели](../../workspace/CANDIDATE_MODEL.md), а не действующему меню.

Профиль хранит собственные данные A/B в `pt006-simulator-content-[A|B]-v6`, Shell — отдельные `pt006-simulator-layout-[A|B]-v3`. Исторические снимки события и PlanRevision — подготовленные. Редактирование JSON не создаёт Actual Event и не переписывает сохранённые архивы. В инспекторе доступны Preview, State, JSON Schema, History; ссылки на отсутствующий объект могут быть предупреждением для черновика.
