# Shell — действующая универсальная оболочка

**Статус: CURRENT для опубликованного Git `main`; незакоммиченные изменения экранов указаны отдельно (снимок 2026-10-11).** Shell управляет отображением и навигацией, но не интерпретирует архитектурные факты или Plan. [Навигатор документации](../README.md) · [Workspace](../workspace/README.md).

## Реализовано

В [src/shell/workspace.ts](../../src/shell/workspace.ts) находятся модель экранов/окон/вкладок и операции `createWorkspaceModel`. В [contracts.ts](../../src/shell/contracts.ts) определены `WorkspaceProfile`, `ContentAddress` и `WorkspaceEvent`. [WorkspaceShell.tsx](../../src/shell/WorkspaceShell.tsx) показывает интерфейс и обрабатывает события, [windowDrag.ts](../../src/shell/windowDrag.ts) — drag, обмен и вписывание окон, [styles.css](../../src/shell/styles.css) — общее оформление.

- **Screen** хранит заголовок и панели. **Panel** — окно с `rect`, списком `tabs` и выбранной `active` вкладкой.
- Пользователь может создавать/удалять/переименовывать экраны, создавать окна, переключать вкладки, переносить и вписывать окна, использовать режим просмотра.
- Вкладки прокручиваются горизонтально; обычное колесо над шапкой вкладок не скроллит доску; колесо над нижней панелью заголовка Shell прокручивает рабочее поле. Ctrl+колесо остаётся браузеру.
- Ограничения `minWidth`, `minHeight`, `maxPerScreen` берутся из `ContentDescriptor` профиля. Они ограничивают **размещение видов**, а не число предметных объектов.
- Закрытие окна, вкладки или экрана не удаляет State/History из профиля.

### Создание экранов: опубликованная и локальная версии

**CURRENT / `main`:** кнопка «+ Экран» создаёт **пустой экран**. Опубликованный `WorkspaceShell.tsx` ещё не предоставляет меню клонирования или профильных шаблонов.

**LOCAL UNPUBLISHED / рабочее дерево:** подготовлены «копия текущего экрана», четыре отдельные профильные заготовки и пакет из четырёх. В локальном коде `duplicateScreen` копирует только окна/размещение и ссылки на те же данные, назначая новые screen/panel IDs; `addScreensFromTemplates` валидирует ссылки, размеры и лимиты и добавляет набор целиком, без частичного применения. **Эта реализация не опубликована вместе с документацией**. Детали и решения перед переписыванием — в [пополняемом плане следующего кода](../workspace/NEXT_CODE_PLAN_CANDIDATE.md). Целевой единый шаблон **контекста** с четырьмя экранами — [кандидатная архитектура](../workspace/CANDIDATE_MODEL.md), не существующее меню.

### Универсальная навигация

```ts
{ type: 'open-content', target: { profileId: 'architecture-simulator', instanceId: 'architecturePlan' } }
```

Shell ищет вкладку сначала на активном, затем на других экранах **текущей раскладки**, активирует вкладку, показывает окно и подсвечивает его. Если зарегистрированного вида нет среди открытых, создаёт новое окно. Неизвестный `profileId` или `instanceId` отвергается, замены не подставляются. Переход **не меняет** предметные факты, Plan или History.

Адрес `{profileId,instanceId}` пока **не содержит идентификатора контекста**. В одном Shell монтируется **один профиль**. Одновременные произвольные окна разных A/B контекстов и настоящие межпрофильные операции не реализованы.

## Контракт и хранение

`WorkspaceShell` получает `WorkspaceProfile`: дескрипторы, `initialWorkspace`, `contexts/contextId`, `layoutKey`, миграцию, рендеринг, инспектор и предметные обработчики. Layout отдельно сохраняется по ключам контекста; Shell не становится владельцем симуляционных данных и не знает `PlanRevision`, Actual Events и A/B. Кнопка демо-сброса после подтверждения сбрасывает текущую раскладку и вызывает `profile.resetContent()`; это не универсальная безопасная операция клонирования контекстов.
