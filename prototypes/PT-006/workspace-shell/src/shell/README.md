# Universal Workspace Shell

Этот каталог не зависит от Architecture Evolution Simulator. Он предоставляет модель экранов, окон, вкладок, их геометрии, навигацию, drag/fit, прокрутку вкладок, режим просмотра и сохранение layout.

Колесо над **любой частью шапки окна** принадлежит полосе вкладок: при переполнении прокручивает их горизонтально, иначе блокирует scroll chaining в рабочую область (в том числе на краях). Вся нижняя панель заголовка Shell (`context-bar`) перехватывает обычное колесо и прокручивает Workspace, а узкая подпись снизу лишь обозначает эту зону. Минимальная высота доски превышает высоту viewport на 300 px: движение возможно даже при небольшом количестве окон. Ctrl+колесо в обеих зонах не перехватывается.

## Подключение профиля

`WorkspaceShell` принимает объект `WorkspaceProfile` из `contracts.ts`. Профиль регистрирует дескрипторы содержимого, определяет свои контексты и ключи хранения раскладок, миграцию старых layout, а также функции отрисовки содержимого, инспектора и собственных управляющих элементов.

Запрос навигации:

```ts
{ type: 'open-content', target: { profileId: 'architecture-simulator', instanceId: 'architecturePlan' } }
```

Shell ищет **адресованный экземпляр** на активном экране, затем на других, выбирает вкладку, прокручивает к окну и подсвечивает его. Если зарегистрированный экземпляр ещё не открыт, создаёт новое окно. Неизвестные цели не подменяются другими вкладками.

`profileId` и `instanceId` не обязаны быть названиями предметных классов. Два документа одного типа должны иметь разные `instanceId`. Текущая интеграция монтирует один активный профиль в один Shell; одновременное смешивание вкладок разных профилей и динамическая загрузка плагинов в этой итерации не реализованы.

## Граница ответственности

- Shell не импортирует `ContentKind`, Plan, Actual Events, State/Schema/History или другие сущности симулятора.
- Профиль сам предоставляет идентификаторы содержимого, представления и предметные операции.
- Общая раскладка отделена от предметного состояния. Конкретный профиль решает, как разложить его контексты по сохранённым layout.
- В реализации PT-006 проверены две независимые раскладки A/B и сохранение существующих ключей `layout-v3`; их смысл остаётся в профиле.
